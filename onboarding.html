STEP 1

  • 마케팅 / 경영지원 — 판다랭크(블로그·스마트스토어), 채널톡, 카카오톡 플러스친구, 네이버 톡톡, 가비아, 아임웹

문의 접수부터 작업 완료보고까지 채널톡으로 오갑니다. 기록이 남아야 나중에 찾을 수 있으니 되도록 채널톡 안에서 주고받으세요.
다만 고객사에 따라 카카오톡으로 소통하는 곳도 있습니다. 담당 현장이 어느 쪽인지 선배에게 먼저 확인하고, 카톡으로 받은 내용은 채널톡이나 업무일지에 옮겨 기록을 남기세요.

STEP 2

부성티케이는 어떤 회사인가

우리가 무엇으로 돈을 버는지 알아야, 내 일이 어디에 붙는지 보입니다.

🏢 회사 주요 업무 및 역량
  • 대형 식당 설계 및 시공 — 대기업과 관공서를 주요 거래처로, 소형부터 수천 식에 이르는 대형 식당의 설계와 시공이 핵심 역량입니다.
  • 냉장·냉동설비 시공 및 유지보수 — 주방설비 분야에서도 고급 기술로 평가받는 냉장냉동설비 기술을 자체 보유하여 설비팀을 운영합니다.
  • 디지털 기반 유지보수 서비스 '왓픽스' 운영 — 오프라인 기반의 전통 산업이지만 디지털화를 통해 혁신하고자 합니다. 왓픽스는 매장 전반의 상황을 파악하는 데 도움을 주는 대표 서비스입니다.

STEP 3

문서 규칙 — 이건 첫날부터 지킵니다

파일명과 이메일은 회사의 얼굴입니다. 규칙이 있으면 나중에 찾을 수 있습니다.

📁 파일명 제작 가이드 내·외부 공유자료 공통 — 이 순서를 지킵니다 ▾
부성_사업장_날짜_내용명_파일형식

예시)

부성_A현장_240214_쇼케이스 냉동고_견적서 부성_B현장_240214_후드교체_작업확인서

파일 유형별 예시

  • 견적서 — 부성_A현장_240214_쇼케이스 냉동고_견적서
  • 거래명세표 — 부성_C현장_201222_오븐납품_거래명세표
  • 기기리스트 — 부성_협력사업_231205_주방기기 투자_기기리스트
  • 도면 — 부성_D현장_230125_메인주방_도면
  • 제품 이미지 — 부성_제조사명_식판 디스펜서 2열_이미지
  • 소견서 — 부성_E현장_230518_워크인 고장수리_소견서
  • 작업완료 확인서 — 부성_D현장_210322_오븐 납품_작업 완료 확인서
🚨 사업장 표기 주의
실제 파일명에는 회사 내부에서 쓰는 사업장 코드를 그대로 넣습니다. 다만 보안구역 고객사의 사업장 코드·현장명은 외부로 나가는 자료(메일 제목, 공개 자료, SNS)에 노출하지 않습니다. 어디까지 써도 되는지 헷갈리면 반드시 먼저 물어보세요.
✉️ 이메일 작성 가이드 고객사·파트너사로 나가는 외부 메일 기준 ▾

제목 — 발신자 정보 + 목적을 함께

  • 잘못된 예 — "안녕하세요. ○○팀 ○○○입니다."
  • 올바른 예 — [부성티케이/A현장] 스팀솥 수리 관련 견적서 및 소견서
  • 요청 건일 경우 "~ 요청 건"으로 표기하면 명확합니다.

본문 — 짧고 명확하게

  • 상단에 인사 + 받는 사람 + 보내는 사람 표기 ("안녕하세요 ○○○ 프로님, 부성티케이 ○○○입니다.")
  • 전달할 내용이 많으면 인사말 뒤에 중요 사항을 먼저 요약
  • 강조 효과는 한 메일에 최대 2가지까지. 많으면 오히려 중요한 게 안 보입니다.
  • 글자색은 파란색·보라색·초록색 위주. 빨간색은 이슈·오류 보고에만 씁니다.
  • 글머리 기호·번호 매기기·표를 활용해 읽기 쉽게

연속성 — 하나의 건은 하나의 스레드로

  • 같은 주제는 답장(Re) 또는 전달(FW)로 이어갑니다. 새 메일을 새로 쓰지 않습니다.
  • 상대 메일에 문의가 여러 건이면 인라인 회신이 편합니다. 내 답변은 형광펜 배경이나 컬러 텍스트로 구분하고, 본문에 "하기 메일에 인라인으로 회신 드리오니 확인 요청 드립니다"를 적습니다.

일정 — 날짜는 정확하게

  • 전달 가능한 일정은 요일까지 명시 ("10월 12일 목요일까지 전달 드리겠습니다")
  • 받아야 하는 일정은 이유와 함께 데드라인을 제시 ("영상 편집 싱크 작업이 있어 10월 6일까지는 필요할 것 같습니다")

마무리 · 발송 전 확인

  • 마무리는 "감사합니다. ○○○ 드림" 고정. 서명에 넣어 두는 것을 권장합니다.
  • 받는 사람은 직접 처리·보고받을 담당자, 참조는 담당자는 아니지만 알아야 할 사람
  • 발송 전 오탈자·맞춤법 반드시 확인
STEP 4

경영지원 프로세스

돈이 오가는 문서는 실수하면 바로 티가 납니다. 확인 항목을 그대로 따라 하세요.

🧾 계산서 발행 (스마트빌) 발행 전에 3가지를 반드시 확인합니다 ▾
  • 공급가액이 맞는지 — 총액과 공급가액을 비교해서 확인
  • 날짜 — 발행하는 날짜에 맞추거나, 요청받은 발행일로 변경
  • 담당자 이름이 맞는지 확인

발행 경로: [복사하여 작성] → [현재 거래처 담당자에게 복사하여 작성] → 기존 내역에서 복사한 것이므로 위 3가지 외에는 수정할 내용이 없습니다.

⚠️ 총액과 공급가액을 헷갈리지 마세요
공급가액은 부가세 별도 금액, 총액은 부가세 포함 금액입니다. 이 둘을 바꿔 쓰면 10% 차이로 잘못 청구됩니다.
📑 거래명세표 발급 (경리나라) 견적서·거래명세표 발급 전용 ▾

경로: [거래처] → [판매관리] → 항목 선택

  • 이메일 발송 — 담당자에게 전송. 간혹 회사 대표 이메일로 설정된 경우가 있으니 수신 주소를 꼭 확인하세요.
  • 메일이 안 나갈 때 — 담당자 이메일이 설정돼 있지 않거나 발송 실패 시, PDF로 저장해서 직접 전송합니다.
🚨 계정 정보는 여기 적지 않습니다
로그인 계정·비밀번호는 이 문서에 적지 않습니다. 필요하면 담당자에게 직접 요청하세요.
STEP 5

일하는 방법 (기획 직군)

마케팅·디자인·기획 업무를 맡는 분들이 먼저 읽는 부분입니다. 현장지원팀은 참고만 하셔도 됩니다.

🧠 기획은 이렇게 합니다 기획의 본질은 문제를 '규정'하는 것 ▾
  • 기획의 본질은 문제를 해결하는 것입니다.
  • 문제는 주어지는 것이 아니라 규정하는 것입니다.
  • 문제 규정이 가장 창의력이 필요한, 기획의 핵심 과정입니다.
💡 기억할 문장
문제는 '나쁜 것'이 아닙니다. '해결해야 하는 것'입니다.

본질을 밝히려면 파고들어야 합니다 — "왜 그런거지?"

두 번이고 세 번이고 "왜?"를 던져 봅니다. 보이지 않는 문제점을 찾는 가장 단순한 방법입니다.

사실 · 현상 · 본질을 구분합니다

가뭄이 들어 농작물이 말라 죽었다 농작물이 말라 죽었다 → 현상 말라 죽는 원인 → 문제 비가 오지 않았다 → 사실 물이 부족하다 → 문제의 본질 ✅

객관적 '사실'을 문제로 규정하는 오류를 주의하세요. 또한 해결할 수 없는 원인은 진짜 문제가 아닙니다.

본질을 밝히려면 높이 올라가야 합니다 — "왜 해야하지?"

고객의 모호한 요청이나 과제는 재해석이 필요합니다. 과제의 목적을 생각하다 보면 문제의 본질이 보입니다.

조사(Research)는 도구입니다. 목적에 따라 얼마든지 변형할 수 있습니다. 통찰로 가설을 만들고, 그 가설을 검증할 최적의 도구를 찾거나 만드세요.

🔍 자료 조사는 이렇게 합니다 시작 전 확인 → 양식 확인 → 찾기 ▾

1. 목적과 용도 확인

  • 왜 찾아야 하는지
  • 무엇을 찾아야 하는지
  • 이 자료가 어디에 쓰이는지

2. 양식과 수준 확인

  • 정리 양식 확인 (엑셀? PPT? 워드?)
  • 기존에 진행했던 유사 사례가 있는지 문의

3. 찾기

💡 두 가지 원칙
① 출처가 명확한 자료만 활용합니다.
② 벌어진 현상(사실)과 필자의 의견을 구분합니다.
  • 기본은 구글링 — 네이버보다 구글, 키워드는 구체적으로(내용·연도)
  • 검색 연산자 — "검색어" 정확히 일치 / 검색어1 -검색어2 제외(하이픈 앞 띄어쓰기) / 기간1..기간2 기간 지정 / 검색어 pdf 파일 형식 지정
  • 글로벌 자료는 영어로 검색
  • 모르는 주제일수록 이미지 검색으로 정리된 PPT·PDF부터 확인
  • 뉴스 기사에 언급된 자료는 출처 원문을 찾아 확인
  • 검색 결과는 3페이지 이상 살펴보기

클라이언트와 제작물의 방향성과 기대치를 미리 확인해서 디자인 작업 리소스를 줄이기 위해 구성안을 씁니다. 양식은 제작물과 상황에 따라 다를 수 있으나, 아래 두 가지는 반드시 포함합니다.

구성 배경 (Why)

  • 클라이언트의 기대나 요청을 명시하고, 이를 어떤 방향으로 풀었는지 목적과 의도를 분명히 전달합니다.
  • 여러 안을 제시할 경우 각 안의 방향성과 목적이 서로 달라야 합니다.

디자인 예시 (How to)

  • 실제 시안으로 제작될 이미지와 최대한 비슷한 레이아웃을 보여주고, 필요한 정보를 상세히 기재합니다.
  • 참고 예시는 이미지를 직접 첨부하거나 확인 가능한 출처를 함께 표기합니다(URL, 스톡 일련번호 등).
